# 故障排查

本页提供当前可执行的通用排查流程，覆盖诊断信息采集、图校验失败和页面加载问题。后续会在此基础上扩展为按症状拆分的专题页。

## 通用排查流程

1. 先确认问题发生在什么层：文档页面、图示 JSON、节点契约，还是应用运行时本身。
2. 记录复现输入：访问页面、图文件路径、节点 key、报错文本、浏览器控制台信息。
3. 对照当前文档版本 `WeConduct 0.8.1`，确认使用的图数据和节点契约没有跨版本混用。
4. 先用最小示例复现，再决定是否扩大到完整项目或更复杂图。

## 诊断信息采集

- 页面侧：记录具体页面 URL、浏览器控制台错误、网络请求失败和资源加载状态。
- 图数据侧：保留原始 JSON，重点检查 `graph_schema_version`、`root_metadata.graph_compatibility`、节点数量、边类型和端口名。
- 文档侧：确认引用路径是否正确，尤其是相对路径和资源是否真的存在于仓库内。

## 图校验问题

- `graph-v1` 不匹配时，先检查顶层 `graph_schema_version`。
- `built_with_app_version` 不是 `0.8.1` 时，先统一图兼容版本，再继续看节点级问题。
- 如果报节点端口或节点 key 不匹配，优先按 WeConduct 0.8.1 的 component manifest 逐项核对。
- 如果图里包含 `observe` 边，当前文档示例校验会拒绝；应改回当前支持的 `control` 或 `data`。

## 页面加载问题

- 如果页面打不开图示，先确认 Markdown 里引用的 JSON 相对路径是否正确。
- 如果页面能打开但图示区域报错，优先查浏览器控制台，再回看图 JSON 是否通过结构校验。
- 如果只是某一页加载异常，先对比 [`内嵌图示`](../reference/embedded-graphs.md) 页面能否正常工作，用它区分是页面引用问题还是通用组件问题。

## 当前边界

- 本页先提供通用流程，不伪造未完成的按症状深链。
- 常见症状会继续拆成独立页面，例如加载失败、版本不兼容、节点契约不匹配等。
