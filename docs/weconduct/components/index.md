# 内置节点

本页是 WeConduct 0.8.1 内置节点目录的真实入口，先说明当前目录结构和检索方式，不虚构尚未落地的节点详情树。

## 当前目录状态

- 当前组件 manifest 共记录 `126` 个节点。
- 其中 `120` 个节点标记为 `component_library_visible: true`，面向组件库和常规使用场景。
- 其中 `6` 个节点标记为 `compatibility_only: true`，主要用于兼容旧图或迁移场景，不应当当作新流程优先选型。
- 当前分组目录数据已整理到 `25` 个组件组；后续会按实际文档产出逐步展开为独立导航和详情页。

## 聚合页与详情页的区别

- 聚合页负责说明一个组件组的范围、共性约束和节点列表，例如浏览器导航组、数据转换组。
- 详情页负责说明单个节点的端口、配置参数、输入输出、副作用和常见错误。
- 当前站点还没有把 `126` 个节点页全部落盘，所以本页先承担目录说明与检索入口职责。

## 当前如何搜索和定位节点

- 站内搜索：直接搜索中文显示名、`resource_key` 或能力域关键字，例如 `browser.navigate`、`导航`、`browser`。
- 数据核对：需要确认节点是否属于公开组件库时，可回查 `data/weconduct-0.8.1/components.json` 里的 `component_library_visible` 和 `compatibility_only`。
- 分组理解：需要先理解一组节点如何配合时，可结合后续分组页规划；当前阶段先以组件 manifest 和图示参考为准。

## 当前可直接使用的参考

- [`内嵌图示`](../reference/embedded-graphs.md)：说明文档里的图示编写方式，适合先解释节点端口和控制/数据流。
- 如果你当前要写组件说明或教学图，先按 `graph-v1` 与 `built_with_app_version = 0.8.1` 的约束准备示例图，再补聚合页和详情页。

## 本页边界

- 本页不伪造尚未创建的组件组链接。
- 真实组件组列表会在后续文档迭代中接到这里，再逐步补齐各组聚合页与节点详情页。
