# 加密参数与待输入

0.9.1 提供两条敏感数据入口：项目设置中的加密初始参数，以及流程运行到 `input.request` 时的待输入表单。两者都把明文限制在当前执行会话内存中，并在日志、事件、诊断、历史和错误摘要中自动脱敏。

## 加密初始参数

在 **文件 → 项目设置 → 加密参数** 中创建加密字段。密码默认每次运行或 Debug 都要输入，密码不会写入项目文件，也不会通过外部 API 或运行日志返回。

初始明文变量与加密参数变量名互斥：只要存在同名字段，保存时就会被拒绝；如果用户直接编辑配置文件制造同名字段，运行准备阶段会报配置冲突，不会静默选择其中一个值。

解锁成功后，参数只在当前运行或 Debug 会话中作为敏感值使用。运行期间可以修改敏感变量，但它仍保持敏感状态，并在 runtime 日志中留下不含明文的 warn 提示。会话结束、取消或终止后，解锁后的内存引用会销毁。

> 不建议把密码、Token、Cookie、认证头或其他敏感值直接写入普通节点配置。节点配置随项目文件保存，可能进入备份、复制文件或版本控制。特殊场景仍可直接配置，但应明确承担泄露风险。

## `input.request` 多字段表单

将[请求输入](../components/input/input-request.md)放入控制流后，执行会话会在该节点暂停，等待整张表单提交。逻辑并行图的实际执行仍是串行调度，因此输入节点会暂停整个执行会话，而不是只暂停某个分支。

每个字段可以声明名称、类型、是否必填和是否敏感，并从列表配置生成独立的数据输出端口。敏感字段不能配置默认值；用户提交后，节点输出的是多个单项值，而不是一个列表对象。

输入方式按运行入口选择：

- 桌面 UI：弹出独立输入窗口；
- CLI：在当前 CLI 会话中填写；
- 外部 API：查询 pending-input 后，通过提交接口发送完整表单。

字段会先整表校验，再一次性提交。缺少必填字段、未知字段或类型错误时，原请求仍保持等待，不会产生部分输出。

## 超时处理

`timeout_seconds` 大于 `0` 才启用超时；`0` 或未设置时不启用。超时后的处理顺序固定为：

1. 如果所有字段都有默认值，使用默认值并继续；
2. 否则尝试连接 `timed_out` 控制端口；
3. 没有默认值且 `timed_out` 未连接时，节点失败。

敏感字段没有默认值设计，因此需要安全输入时应使用 UI、CLI 或外部 API 提交。

## 日志与 Debug

运行日志、事件流、历史、诊断和待输入查询只显示字段定义、类型、敏感标记和 `<redacted>` 占位符，不显示敏感值。Debug 在暂停快照中允许用户按需查看敏感变量，但每次查看需要再次输入项目参数密码；明文只在当前 Debug 会话内存中短暂存在，不写入 Debug 历史或持久化快照。

如果运行提示 `unlock_required`，先完成项目解锁，再处理待输入窗口。点击终止会结束等待状态并清理敏感内存；待输入窗口应随会话终止关闭。
