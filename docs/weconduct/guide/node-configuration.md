# 节点配置

节点配置保存在 `node_config`。编辑器根据组件声明的字段模板和参数 schema 选择控件，不同节点不会共享一张固定表单。

## 字段编辑器

- 文本、数字、布尔值：直接输入或切换。
- `typed-value`：区分字符串、数字、布尔、对象等类型，避免把所有值保存成文本。
- 对象映射：用于变量表、输入/输出映射。
- `component-schema`：用于 `component.input` 和 `component.output` 的字段、类型与必填规则。
- 分支列表、代码等复杂值：在元数据编辑面板完成。

节点上的行内摘要只展示适合快速修改的字段；完整配置以 **元数据编辑** 面板为准。

## 端口与配置

部分控制节点的分支配置会影响端口集合。修改后应重新检查已有边，避免引用已删除端口。保存或编译时，服务会校验端口存在、方向和关系层。

## 保存冲突

图编辑请求带有保存版本。另一个窗口或异步刷新先写入时，可能出现图稿版本冲突。默认 `save_conflict_policy` 倾向保留当前图；严格模式会要求先刷新再重做修改。不要用旧 JSON 覆盖新版本。

## 与 Debug 配置的边界

断点和记录帧可保存在节点 `debugger` 配置中，但 Debug 期间的变量内联编辑属于会话状态，不会自动改写节点配置。不要把 Debug 变量覆盖当成 `node_config` 保存。
