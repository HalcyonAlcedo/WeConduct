# 控制流与数据流

## 控制流

`relation_layer = "control"` 的边决定节点何时执行。标准主图从唯一的 `flow.start` 出发，沿控制后继关系调度节点。

在首个项目中：

```text
开始.out → 写入变量.in → 读取变量.in
```

如果节点没有从入口可达，编译验证会报告不可达节点。分支、循环、并行和重试节点会对控制后继关系施加额外语义。

## 数据流

`relation_layer = "data"` 的边把源端口产生的值传给目标数据输入端口。两端端口都必须声明为数据层；控制端口不能连接到数据端口。

数据边不自动决定执行顺序。需要“先产生值，再消费值”时，通常还要有对应的控制路径。

## 变量与节点输出

WeConduct 还有两种取值方式：

- `${name}`：读取运行时变量。
- `${node.<node_id>.<field>}`：读取节点输出中的字段。

完整字符串只有一个引用时保留原始类型；引用嵌入普通文本时会转换为字符串，列表和对象会序列化为 JSON 文本。

首个项目的 `data.get_variable` 通过变量名读取变量表，不接受数据输入，所以示例只连接控制边。
