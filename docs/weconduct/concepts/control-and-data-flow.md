# 控制流与数据流

WeConduct 的节点图有两种并行的"流"：控制流决定执行的先后顺序，数据流决定数值的传递路径。把它们分开设计，是为了让你能灵活地组合和控制流程。

## 控制流：决定"谁先谁后"

控制流通过**控制边**（蓝色实线）来传递。它告诉 WeConduct：这个节点执行完之后，下一个应该执行哪个节点。

流程总是从唯一的**开始节点**出发，沿着控制边一步步走到终点。如果某个节点有多条控制输出（比如条件分支），只有满足条件的那条路径会被执行。

```text
开始.out → 写入变量.in → 写入变量.out → 读取变量.in
```

在一个简单的流程里，节点按控制边的方向顺序执行。但如果图中的某个节点没有控制路径可以从开始节点到达，编译时会报告"不可达节点"，这个节点就不会被执行。

## 数据流：决定"值怎么传"

数据流通过**数据边**（绿色虚线）来传递。它把一个节点产生的具体数值传到另一个节点的参数上。

比如，HTTP 请求节点请求了一个 JSON 接口，返回的数据可以通过数据边传给"写入变量"节点存储起来，或传给"Python 执行"节点做进一步处理。

数据边只管传值，不管执行顺序。所以，如果你需要某个值在 B 节点执行时已经准备好了，除了用数据边传值之外，还要确保控制边会让产生值的节点先执行。

## 变量：另一种传值方式

除了数据边，WeConduct 还支持通过变量来传递数据：

- **`${变量名}`**：读取运行时变量的值。比如在配置中写 `${user_name}`，运行时会替换为变量 `user_name` 的实际值。
- **`${node.节点ID.字段}`**：读取某个节点执行后的输出字段。比如 `${node.node-2.body}` 可以获取 HTTP 请求的响应正文。

当你引用的是一个纯变量或节点输出（整个字符串就是一个引用），值的原始类型会被保留；如果把引用嵌入到普通文本中，值会先转成字符串。

## 两者怎么配合

控制流和数据流各司其职：

- 用**控制边**搭建流程骨架，决定先做什么、后做什么、什么条件下走哪条路
- 用**数据边**或**变量引用**传递数据，让下游节点拿到上游节点的处理结果

一个常见的模式是：控制边串联执行顺序，数据边在需要的节点之间显式传值。
