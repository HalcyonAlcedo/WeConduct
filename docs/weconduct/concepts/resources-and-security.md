# 资源与安全

WeConduct 的自动化流程可以操作文件、访问网络、控制浏览器——这些能力很强大，但也需要你在使用前先理解安全模型，确保流程在受控的环境下运行。

## 最小权限原则

WeConduct 默认关闭了大部分高风险能力。运行一个流程时，程序会根据你实际用到的节点，告诉你需要开启哪些权限。你可以选择性地只开启必要的权限，而不是全部打开。

这是一个有意识的安全设计：你写的自动化流程只拥有你明确授予的能力，不会偷偷多做什么事情。

## 项目资源范围

项目中使用的文件路径（如读取的 CSV、输出的 Excel、引用的图片等）默认以项目目录为根目录解析。也就是说：

- `sample/input.csv` → 你的项目目录下的 `sample/input.csv`
- `output/report.xlsx` → 你的项目目录下的 `output/report.xlsx`

转移项目到另一台电脑时，只要整个项目目录一起移动，所有路径引用仍然有效。

## 有哪些安全控制

WeConduct 0.8.1 的安全策略涵盖以下几个方面：

### 默认关闭的能力

- 文件访问（项目目录外的文件读写）
- 外部程序调用
- 浏览器执行器
- 浏览器下载功能
- 本地网络访问
- 远程网络访问
- Python 代码执行
- JavaScript 注入与求值

### 默认开启的能力

- 浏览器截图
- Cookie 操作
- 浏览器存储（Local Storage/Session Storage）
- 文件上传
- 新窗口控制

## 开启权限后

开启文件访问权限后，默认范围仍然是"受限"——程序只能访问你明确配置的目录，加上当前项目目录和工作区目录。你可以通过 `file_access_allowed_roots` 添加更多的允许路径。

即使允许了某个目录，程序还会继续检查阻止目录列表和文件扩展名白名单/黑名单。只有显式设置为 `allow_all` 时才会跳过这些限制——但这通常不推荐，除非你完全信任流程的来源。

## 安全管理建议

1. **先用默认设置试运行**，查看诊断信息中提示缺少哪些权限。
2. **根据错误提示逐个开启**，不要一次性把所有权限都打开。
3. **只对当前项目开放**，并尽可能缩小文件目录和网络目标的允许范围。
4. **运行完成后复查**项目设置、网络访问目标和输出的文件。

对于 `.wcrun` 运行包（从别人那里获取的流程），加载前会执行预检，汇总所需的资源、依赖和权限要求。对来源不明的包，不建议授予 Python 执行、脚本注入或广泛的文件写入权限。
