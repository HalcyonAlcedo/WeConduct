# 子图与自定义组件

当你的自动化流程越来越复杂时，你可能会发现某些操作步骤反复出现。这时候，你可以把这些步骤打包成一个**自定义组件**（子图），在需要的地方像内置节点一样直接调用。

## 什么时候适合创建自定义组件

- 同一个操作组合在多个流程中都会用到（比如"登录验证"、"数据清洗"）
- 某个流程片段逻辑完整、职责清晰，可以独立封装
- 你想把复杂的主图拆分成几个更小、更容易理解的模块

如果某个流程片段只用一次，而且不会复用到其他地方，通常保留在主图中就可以了，不必为了封装而封装。

## 输入与输出边界

每个自定义组件需要明确声明它的"接口"——它能接收什么、能输出什么。这是通过两个特殊的边界节点来定义的：

- **组件输入**（`component.input`）：声明组件需要调用方提供什么数据。比如一个"文本规范化"组件可能需要一个 `text` 输入。
- **组件输出**（`component.output`）：声明组件完成后能返回什么数据。比如"文本规范化"组件处理完之后会输出 `normalized`。

调用方传入的字段和类型必须与组件声明的输入匹配，否则会报错。这就像函数的参数和返回值——类型必须对得上。

## 在哪里编辑

自定义组件保存在项目的资源目录中。你可以在**资源管理**面板中打开组件图，像编辑主图一样拖拽节点、配置参数和连接端口。编辑完成后保存，组件就会在主图的组件库中出现。

## 运行时的隔离

组件运行时使用独立的子运行上下文。它可以访问运行设置、项目目录和指定的变量，但不能随意访问调用方的内部状态。这种隔离让组件更稳定可靠，不会因为外部环境变化而出现意外行为。
