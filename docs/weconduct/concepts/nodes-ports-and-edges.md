# 节点、端口与边

在 WeConduct 中，所有的自动化流程都由三个基本元素组成：**节点**、**端口**和**边**。理解它们各自做什么、怎么配合，是使用 WeConduct 的基础。

<weconduct-graph src="../../assets/graphs/getting-started/first-project.json" title="节点、端口与控制边">如果图示加载失败，请阅读下方的说明来理解这三个概念。</weconduct-graph>

## 节点：流程的"动作块"

节点是流程图中一个个带标签的矩形块。每个节点代表一个具体的操作或逻辑单元，比如：

- **开始节点**：标记流程的入口
- **浏览器导航节点**：在浏览器中打开一个网址
- **写入变量节点**：设置一个变量的值
- **条件判断节点**：根据表达式的真假走不同分支

每个节点都有：
- **节点名称**：画布上显示的标题
- **资源键**：节点的唯一标识符，比如 `browser.navigate`、`data.set_variable`
- **配置参数**：控制节点行为的具体设置，比如 URL、变量名、超时时间等

## 端口：节点的"接口"

每个节点的左右两侧有一些小圆点，这就是端口。端口是节点对外连接的唯一通道：

- **输入端口**（左侧）：接收前一个节点的控制信号或数据
- **输出端口**（右侧）：向后一个节点发送控制信号或数据
- **控制端口**（蓝色）：传递执行顺序的信号
- **数据端口**（绿色）：传递实际的数据值

一个节点可以有多个端口。比如"条件判断"节点有 `true` 和 `false` 两个输出端口，分别对应条件成立和不成立时的走向。

## 边：节点之间的"连线"

边就是连接两个端口的线，它决定了两件事：

- **控制边**（实线）：决定"什么时候执行"。控制边从上一个节点的输出连到下一个节点的输入，构成了一条执行链。
- **数据边**（虚线）：决定"数据怎么传"。数据边把上游节点产生的值传到下游节点需要这个值的参数上。

连接时，必须把相同类型的端口连在一起（控制端口连控制端口，数据端口连数据端口），否则流程校验时会报错。

## 总结

简单来说：

- **节点** = 做什么
- **端口** = 能接收什么、能输出什么
- **边** = 什么时候做、数据怎么传

把它们组合起来，就构成了一个完整的自动化流程。
